# Dependency Update PoC

A proof-of-concept for pinning all dependencies to cryptographic hashes and automating updates via [Dependabot](https://docs.github.com/en/code-security/dependabot) and [Renovate](https://docs.renovatebot.com/).

## What this demonstrates

Most projects pin dependencies to a version number (`flask==3.1.3`, `node:22-slim`). This is better than nothing, but version tags are mutable — a registry or package index can serve different content under the same tag. Pinning to a **cryptographic hash** guarantees you get exactly the bits you tested, every time.

This repo shows how to do that across five ecosystems and how to keep those hashes up to date automatically without manual effort.

## How hash pinning works per ecosystem

### Python (`python-app/`)

`pip-tools` is used to manage dependencies. You declare direct dependencies in `requirements.in` and run `pip-compile --generate-hashes` to produce `requirements.txt` — a fully resolved lockfile containing `sha256` hashes for every package, including transitive dependencies.

```
# requirements.in  ← you edit this
flask

# requirements.txt  ← generated, committed, never edited by hand
flask==3.1.3 \
    --hash=sha256:0ef0e52...
werkzeug==3.1.8 \
    --hash=sha256:63a77fb...
    # via flask
```

The Docker build uses `pip install --require-hashes -r requirements.txt`, which makes pip verify every hash and refuse to install anything not listed. CI also regenerates the lockfile and diffs it to catch any drift between `requirements.in` and `requirements.txt`.

To update the lockfile locally:
```sh
pip install pip-tools
pip-compile --generate-hashes requirements.in
```

### .NET (`dotnet-app/`)

NuGet's lockfile (`packages.lock.json`) contains `sha512` content hashes for every resolved package. Enable it in the `.csproj`:

```xml
<PropertyGroup>
  <RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>
</PropertyGroup>
```

Then `dotnet restore --locked-mode` in CI enforces that the lockfile is used exactly as committed.

### Node.js (`nodejs-frontend/`)

pnpm is used as the package manager. `pnpm-lock.yaml` contains `sha512` integrity hashes for every installed package. `.npmrc` sets `save-exact=true` to prevent `^` or `~` ranges being added by `pnpm add`.

```yaml
# pnpm-lock.yaml (excerpt)
express:
  specifier: 5.2.1
  version: 5.2.1

packages:
  express@5.2.1:
    resolution:
      integrity: sha512-hIS4id...
```

The Docker build and CI both use `pnpm install --frozen-lockfile`, which fails if `pnpm-lock.yaml` is missing or out of sync with `package.json`.

The pnpm version itself is pinned via the `packageManager` field in `package.json` and activated through corepack:

```json
"packageManager": "pnpm@10.33.0"
```

### Go (`golang-app/`)

Go's module system has hash pinning built in. `go.sum` contains `h1:` hashes for every module (direct and transitive). The Go toolchain refuses to use any module whose hash isn't in this file.

```
github.com/some/module v1.2.3 h1:abc123...
github.com/some/module v1.2.3/go.mod h1:def456...
```

`go mod verify` in CI checks that all downloaded modules match the hashes in `go.sum`. Adding or removing a dependency updates `go.sum` automatically via `go mod tidy`.

### Docker base images (all apps)

Every `FROM` line is pinned to an immutable digest rather than a mutable tag:

```dockerfile
# Tag alone — mutable, can change without notice
FROM python:3.12-slim

# Digest — immutable, always the exact same image
FROM python:3.12-slim@sha256:804ddf32...
```

The tag is kept as a comment for human readability. Dependabot and Renovate update both the digest and the comment tag together.

### GitHub Actions (`.github/workflows/`)

Every action is pinned to a commit SHA rather than a version tag. Tags like `@v4` are mutable and can be moved to point at different (potentially malicious) commits — a supply chain attack vector.

```yaml
# Tag alone — mutable
- uses: actions/checkout@v4

# Commit SHA — immutable
- uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6.0.2
```

### Terraform (`terraform/`)

The Terraform provider lockfile (`.terraform.lock.hcl`) is generated by `terraform init` and contains `h1:` hashes for every provider. It must be committed to the repo. Terraform will refuse to use a provider whose hash doesn't match.

```hcl
provider "registry.terraform.io/hashicorp/null" {
  version     = "3.2.3"
  hashes = [
    "h1:I0Um8UkrMUb81Jбbz...",
  ]
}
```

## Automated updates

Both Dependabot and Renovate are configured to raise PRs when newer versions are available. They update the version **and** the hash together in the same PR, so the security guarantee is maintained automatically.

### Dependabot (`.github/dependabot.yml`)

| Ecosystem | Directory | Notes |
|-----------|-----------|-------|
| `pip` | `python-app/` | Updates `requirements.in` and regenerates `requirements.txt` |
| `nuget` | `dotnet-app/` | Updates `.csproj` and `packages.lock.json` |
| `npm` | `nodejs-frontend/` | Detects `pnpm-lock.yaml` and updates it automatically |
| `gomod` | `golang-app/` | Updates `go.mod` and `go.sum` |
| `terraform` | `terraform/` | Updates `main.tf` and `.terraform.lock.hcl` |
| `github-actions` | `/` | Updates SHA and keeps the `# vX.Y.Z` comment in sync |
| `docker` | `python-app/`, `nodejs-frontend/`, `golang-app/` | Updates image digest SHAs |

> **Note:** `dotnet-app/` Docker images (`mcr.microsoft.com`) are excluded from Dependabot's Docker ecosystem — Dependabot returns `DockerRegistry2::NotFound` for MCR images due to an API incompatibility. Renovate handles these instead.

> **Docker Hub authentication:** Dependabot's Docker updater is unauthenticated by default and will hit Docker Hub rate limits. The `dockerhub` registry block at the top of `dependabot.yml` passes credentials via the `DOCKERHUB_USERNAME` and `DOCKERHUB_PASSWORD` Dependabot secrets (Settings → Secrets and variables → Dependabot). Use a Docker Hub access token, not your password.

All ecosystems are configured with:
- **`cooldown: default-days: 2`** — only raises a PR if the new version is at least 2 days old, reducing exposure to packages yanked shortly after release
- **Groups** — minor and patch updates are bundled into one PR per language; major updates each get their own PR

### Renovate (`renovate.json`)

Renovate covers the same ecosystems as Dependabot and additionally handles the MCR Docker images that Dependabot cannot. `"pinDigests": true` ensures Renovate will pin any new dependencies it encounters to a digest rather than a floating tag.

## Why use both Dependabot and Renovate?

They complement each other. Dependabot is built into GitHub and requires no setup beyond a config file. Renovate is more flexible and supports a broader range of registries (notably MCR). Running both provides redundancy and catches cases where one tool has ecosystem-specific limitations.
